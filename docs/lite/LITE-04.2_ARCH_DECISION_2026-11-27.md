## 2. 架构裁决

**批准方案：受控单数字优先尝试自制字形的 Maa `JTemplateMatch` 与 Maa `JOCR`/`only_rec` 的双路径验证；保留 Maa JOCR 识别题号、倒计时、正/负/多位分数。** 这属于可控 Quiz 视觉适配，不是另造通用 OCR 或回退旧 BCA-04 算法。

### 2.1 按实验证据选择单数字仲裁策略

1. 对题目和 A/B/C/D 的五个单数字字段制作 **0..9 共十种自制、明确来源/许可的规范化字形资产**，由页面受控字体/字体变体生成或使用自制矢量字形；在 Maa 原生 `JTemplateMatch` 内按同一截图、准确 ROI、实际尺寸/缩放匹配。不能直接拿某次运行截图裁剪的动态像素作生产模板，也不应把测试 oracle 的答案编码进模板名/调用。
2. 对每个 ROI 收集各数字候选、原生 score、候选数、最好与次好的差距、ROI 和模板资产 ID；在算法实测前**不预定万能置信度阈值**。出现多个近似候选、框越界、尺寸不匹配一律 AMBIGUOUS/NOT_FOUND。
3. 同图保留 JOCR `det+rec` 与/或受控紧 ROI 的 `only_rec` 实验。**当 OCR 有明确数字且与模板结果冲突时，哪怕 OCR score 不高，也必须保守拒绝；不得以两者中分高者决定答案。** OCR 缺失/低于可信范围时，是否允许模板独立主判定，必须以独立未参与调参样本上零错误 MATCHED、充分覆盖、模板最大/次大 margin 明确且速度达标为前提；未验证前先拒绝。
4. **第一轮只做对照实验，第二轮才落实 QuizPlugin 判定策略。** 若 native 模板辨认 1/7 或 6/8 等仍不稳定，优先对**自制 Quiz 页面**试验字号/字重/字符间距/字形资产、或以一套显示给人看的固定字形资源渲染单数字，让视觉资产与页面字体一一对应；真实用户可见性须保持。字体改动属于受控 demo 布局调整，不触碰隐藏 DOM 数据。
5. 在确定模板管线成本之后核对 Maa v5.16.1 `JTemplateMatch` 支持的多模板/结果格式；避免未经证实就假设一次 recognition 可以把十种模板分类成带模板 ID 的结果，必要时逐个请求并测成本。保持 `MaaVisionFacade` 一截图多识别及同一个精确 ObservationRef。
6. 多数字段使用本次 Maa OCR 且严格解析，不借旧帧内容弥补缺失。`score=0` 有效；负号和多位数必须整串可信，否则只读提示识别失败，不发布可执行状态。题号不能靠题目/四选项拼接代替真实可见 round_mark。

### 2.2 必须保持的安全边界

- `MATCHED` 不仅要求页面选项自洽，还要求本次**题目和四个数字都有已经实测可辨错的独立视觉依据**；任何两路冲突/来源不确定/候选不唯一均不给动作 target。
- 检测到数字与识别出正确数字是两个不同的测试结果：不能以 Job.succeeded、OCR 检测框、单个 best 候选或纯业务自洽代替语义正确。
- QuizPlugin 只读 Maa 同批截图结果；DOM/`quizTest` 只在测试中激励/核对，不进入识别/动作路径。保持 `require_authorization`、双重输入确认、Target/几何时效和关闭保护。
- 不降低 04.3 的双步骤前/后新观察、同轮校验和结算语义；04.2 尚未验收前不得接入真正的 A/B/C/D 自动作答。

## 3. Codex 补充验证顺序（按子步骤提交，不重写架构）

**04.2a · 纯识别诊断：**

- 在**同一批原始 PNG**上复放 JOCR det+rec、only_rec、不同 48～80px 字号/字重候选和 native 数字模板，记录每一数字的**全候选**、置信度、1↔7及6↔8混淆表、所用 ROI 与匹配成本。仅此步不得据此宣称真实 Edge 支持。
- 对原始漏识别6和误识别1→7两条失败样本必须单独列出结论。保留历史失败日志，不覆盖原文件；自制模板的生产/许可/哈希说明纳入仓库。

**04.2b · 真实 Edge 矩阵与盲样：**

- 控制测试 seed/时钟，将 0..9 每个数字轮流作为题目、四个选项均覆盖各数字；至少 **DPR 1/1.5/2 × raw/nonraw × 3组不同seed/轮次**，每组覆盖全部十个题目数字。再覆盖真实 Edge 页面缩放 80/100/125% 和已有 56px 负例/受支持字体变化；测试样本与阈值调参样本分开。
- 每条记录原始 PNG、实际送 Maa 图、Frame ID/ObservationRef 关联、完整 native request/candidates、业务状态、DOM oracle、耗时。**不允许仅记录最终成功数**。主动加入模糊、低对比、部分遮挡、ROI偏移、相似字形和候选冲突；未支持字体/缩放必须安全拒绝。
- **验收最低条件：独立未参与调参矩阵中 0 次错误 `MATCHED`；预定支持配置的完整可信 `MATCHED` 率至少 95%；全部十个数字都有真实正确实例；所有歧义/不确定均拒绝写入。** 这是受控 Quiz 的可用性目标，不是误差率统计置信上限或对任意网页的承诺。

**04.2c · 性能、资源与分发：**

- 真实 Edge 中连贯观察至少60秒，实测**≥1Hz 有效视觉观察**（来源有效、全字段可信、未过期才计 valid）；列 median/p95 capture、native、parse、total、CPU、RSS、PrivateBytes、1Hz失败情况和安全退化策略。不能用单次0.2秒 native调用假称完整闭环1Hz。
- 验证包内模板及模型manifest在**干净wheel安装、异cwd**加载；原生 Controller/Resource/Tasker 与模板临时目录生命周期对应，结束 released=True，原有 Target 保留、pending=0。

**若04.2b/04.2c不达标：** Codex 提供两条已经测过的方案的覆盖率/误认率/CPU和最小布局差异，主会话再裁决是否调整受控页面字体或缩放支持策略。不能以阈值提高后全部拒绝当作功能通过。
