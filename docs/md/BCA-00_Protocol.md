## 1. 项目背景

**项目名称：** Browser CLI Agent（BCA）

BCA 是一个通用浏览器页面感知与输入控制框架。

系统通过浏览器能力接口获取指定页面的画面或其他页面信息，由插件解析为结构化状态，再通过 CLI 呈现给用户。用户输入经过插件解析与动作映射后，通过 Core 执行相应的浏览器输入事件。

项目采用三个主要层级：

- **Core：** 浏览器连接、Provider 能力接口、任务调度、事件管理、动作执行、插件生命周期、公共数据模型。
- **Plugin：** 图像处理、资源管理、页面信息解析、状态格式化、命令解析与动作映射。
- **Application：** CLI 输入输出、运行控制、配置与诊断。

所有子系统在同一个 Git 仓库和项目根目录下开发。

## 4. 公共数据协议

在 `bca.core.protocol` 下定义公共数据模型。

### 4.1 Frame

表示浏览器采集的一帧画面。包含：

- 唯一帧 ID
- 采集时间戳
- 图像宽高
- 图像数据与编码格式
- 页面视口与坐标相关元数据
- 来源页面或会话标识

明确原始图像数据的表示方式及生命周期，优先保证跨模块传递的低开销与类型一致性。

### 4.2 PageState

表示插件解析出的页面状态。包含：

- 插件标识
- 状态版本或序号
- 来源帧 ID（可选）
- 生成时间戳
- 结构化数据
- 必要的识别状态和诊断信息

具体页面状态使用插件自定义的数据 Schema，Core 将其作为不透明数据处理。

### 4.3 Command

表示来自 CLI 或其他输入端的规范化命令。

包含命令名称、参数、请求 ID 和来源信息。

### 4.4 Action

表示发送至浏览器的标准化输入动作。初步支持：

- 鼠标点击
- 鼠标移动
- 鼠标按下与释放
- 键盘按下与释放
- 文本输入

定义明确的动作参数、坐标系、执行顺序和错误模型。

### 4.5 ActionResult

表示动作执行结果，包括动作 ID、执行状态、时间信息和错误详情。

### 4.6 Event

表示 Core 或插件产生的事件，包含事件类型、事件来源、时间戳及结构化附加数据。

事件类型应具有可扩展性。

## 5. Provider 接口

设计 Provider 抽象及能力标识机制。

Provider 用于向插件提供由 Core 管理的能力。要求：

- 支持按能力名称或类型查询。
- 支持能力可用性检查。
- 支持未来扩展新的 Provider 类型。
- 保持 Provider 注册与具体实现解耦。

首批定义：

- **Capture Provider：** 获取页面截图及截图元数据。
- **Input Provider：** 执行标准化输入动作。

Provider 架构应允许未来添加 DOM 等其他能力，实现与接口可按对应子系统的开发需求逐步确定。

Provider 接口应明确同步/异步语义、异常处理及生命周期约定。

## 6. Plugin 接口

设计插件基础协议和 `PluginContext`。

插件能够：

- 声明插件 ID、版本及所需能力。
- 在初始化时获取上下文。
- 通过 Provider 获取页面数据。
- 将页面信息转换为 `PageState`。
- 接收和解析用户命令。
- 将命令转换为标准化 `Action`。
- 按生命周期进行启动、停止和资源清理。

插件的页面信息获取方式由自身决定。

识别数据、页面展示格式与动作映射规则由插件定义。

## 7. 依赖约束

遵循以下依赖方向：

- `core.protocol` 独立于浏览器实现、CLI 和具体插件。
- `core.providers` 使用公共协议。
- `core.runtime` 使用公共协议和 Provider 抽象。
- `plugin_sdk` 使用公共协议及公开的 Core 接口。
- `app` 依赖 Core 公开接口。
- 具体插件依赖公共协议、Provider 和可选的 Plugin SDK。

通用公共模型集中定义，避免循环依赖与重复实现。
