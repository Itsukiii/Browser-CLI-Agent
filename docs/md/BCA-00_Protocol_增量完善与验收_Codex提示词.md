## 3. 类型与依赖选择

- 基础模型优先使用 Python 3.12+ 标准库：`dataclasses`、`enum`、`typing.Protocol`、`abc`（按实际情况选用）、`datetime` 等。
- 公共模型提供明确类型注解，适合静态类型检查；需要运行时校验的关键不变量在模型入口进行校验。
- `core.protocol` 保持最小依赖，不依赖浏览器、图像识别、CLI、具体插件，也不引入为统一 Schema 而强制使用的运行时模型框架。
- 对象在单进程模块之间按 Python 类型传递；需要日志、配置、持久化或外部交换时使用明确的 JSON 兼容表示，不要求所有对象自动 JSON 化。
- 保持 `src/` 布局、现有项目包路径及最小运行时依赖。

## 4. 公共模型完善要求

实现位置以现有 `bca.core.protocol` 合理结构为准，允许拆分模块并从 `__init__.py` 集中导出稳定的公开符号。

### 4.1 Frame

必须明确并实现：
- 帧唯一标识、来源页面/会话标识、采集时间戳、图像编码格式、宽高、编码后的二进制数据、视口和坐标元数据。
- 默认使用不可变 `bytes` 保存**编码后的截图**（如 PNG/JPEG），在内部传递时不做无谓复制；通过明确的编码枚举或受控字符串声明格式。图像解码由使用者按需进行。
- 明确 `width` / `height` 是截图实际像素尺寸，视口尺寸以 CSS 像素计量，并显式区分两者。描述缩放、设备像素比和截图裁剪偏移所需的映射信息。
- 为常用输入场景规定**CSS viewport 坐标**作为标准鼠标动作空间：原点位于视口左上角，x 向右、y 向下。截图像素坐标必须通过帧元数据转换，不依赖假定的固定比例；非等比缩放、裁剪偏移及浏览器缩放均应在文档中说明。
- 提供清楚的帧数据生命周期说明：Frame 持有的 `bytes` 在对象存活期间有效；使用者可持有 Frame 引用；跨异步任务传递时不应复用或原位修改其二进制存储。
- 校验基本有效性（尺寸为正、时间戳有效、图像字节内容与声明类型的基本要求等）；具体图像完整性校验由图像层负责。

### 4.2 PageState

- 包含插件 ID、插件状态版本或序号、生成时间戳、可选来源 Frame ID、结构化数据和识别/诊断信息。
- Core 对插件专用数据保持不透明，仅对外层公共字段实施统一规范。
- 明确状态版本与数据 Schema 版本是否分离；二者语义须清晰，命名一致。
- 结构化数据优先采用 JSON 兼容的常规数据类型，以便 Runtime 存储和 CLI 展示；定义浅层引用/可变性约定，避免跨任务意外修改。

### 4.3 Command

- 包含命令名称、参数、请求 ID 和来源标识，定义参数格式与关键字段验证。
- 明确命令是规范化后的输入数据；插件负责具体页面命令语义。

### 4.4 Action

- 明确动作 ID、动作类型、目标及类型相关参数。
- 支持鼠标点击、移动、按下/释放，键盘按下/释放，以及文本输入。
- 校验动作种类与必要参数匹配，例如鼠标动作使用坐标、键盘动作要求键标识、文本动作要求文本。
- 统一以 CSS viewport 为默认鼠标输入坐标语义，允许在接口层明确扩展其他空间，但必须显式标记及转换。
- 规定动作顺序：Input Provider 对上层依次 await 的动作按顺序执行；并发动作的调度责任由调用方承担。定义取消与部分失败时结果或异常的表达方式。
- 基础模型不绑定特定 CDP 事件细节。

### 4.5 ActionResult

- 包含对应动作 ID、明确的成功/失败状态、开始/完成时间及可选错误详情。
- 设计足够表达 Provider 返回的可预期动作执行失败；与接口级异常区分。

### 4.6 Event

- 包含事件类型、来源、时间戳及结构化附加数据；事件类型具有扩展空间。
- 定义公共事件类型的最小集合或命名约定，允许后续模块扩展，而无需修改 Core 基础模型。

### 4.7 统一数据约定

- 明确时间戳的时区与精度（推荐带时区的 UTC `datetime`，若已有统一实现可沿用合理等价方案），以及事件顺序/耗时测量如何避免混淆墙上时间与单调时间。
- 明确标识字段的类型、生成职责、唯一性范围。
- 模型默认值应避免可变对象共享；明确可变载荷的所有权约定。
- 为需要跨模块序列化的轻量对象提供可测试的字典/JSON 转换机制（可为独立 codec 模块）；包括枚举、时间戳和嵌套数据的往返处理。Frame 的图像 `bytes` 保持内部二进制形式，序列化接口允许只输出元数据；若确需完整 JSON 表示，则显式采用 Base64 并说明成本，不能静默将大型字节数组展开。

## 5. Provider 公共接口

- 定义异步 Capture Provider 与 Input Provider 公共契约：截图返回 Frame；输入接受标准 Action、返回 ActionResult。
- 使用 `async def` 作为采集与输入操作的默认调用语义；接口层应可被 mock/fake 实现而无需真实浏览器。
- 定义 Provider 能力标识、注册和查询的稳定方式，支持按能力名或类型查询、可用性检查和后续扩展。
- 定义生命周期边界（初始化/启动/关闭或项目当前合理等价方法）、调用前置条件和异常语义。
- 区分能力不存在、Provider 当前不可用、参数非法、执行过程中发生错误等类别，提供统一基础异常定义。
- Provider Registry 的具体实现仅限实现基础接口可验证行为，与后续 BCA-01/02 的实现职责兼容。

## 6. Plugin 公共接口

- 定义元信息（插件 ID、版本、所需 Provider 能力）与 `PluginContext`。
- 定义异步生命周期契约及插件读取信息、产生 PageState、处理 Command 并输出 Action 的调用方式。
- 插件可根据自身需要主动通过 Provider 获取页面信息；公共接口应同时支持运行时获取状态或发布状态的清晰路径。选定一套主路径，确保不会出现两种含糊的发布机制；在文档中给出最小调用示例。
- `PluginContext` 提供必要的 Provider 访问、插件配置和状态发布能力，其引用方向不得造成循环依赖；考虑以 Protocol 类型定义状态发布/上下文能力，由 Runtime 在 BCA-02/03 实现注入。
- 具体插件的识别算法、输出 Schema 和命令映射保持插件侧定义。
- 为示例插件或测试 fake 提供最小可运行实现，证明接口可集成。
